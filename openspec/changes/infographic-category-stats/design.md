## Context (背景情境)

首頁目前顯示的分類統計區塊，是一排白色卡片，上面只有簡單的資料夾圖示與數量。使用者希望將這裡改造成更吸引人的「資訊圖表」風格，讓數字更突出，並透過更好的視覺設計來傳遞這些數據。

## Goals / Non-Goals (目標與非目標)

**Goals (目標):**
- 替換現有的分類統計卡片，改為更有動態感、視覺更豐富的設計。
- 運用多樣的顏色、進度條式的指示器或大膽的字體，營造出資訊圖表的氛圍。
- 直接使用 Tailwind CSS 類別與現有的圖示/SVG 來實作設計。
- 維持響應式排版（在手機上正確堆疊，在電腦上並排或使用網格顯示）。

**Non-Goals (非目標):**
- 不改變後端的資料來源（分類名稱與數量依然來自現有的資料庫/變數）。
- 不引入肥大的圖表 JS 套件（例如 Chart.js 或 D3.js），除非絕對必要；為了維持網頁高效能，我們優先使用 CSS 來實現圖表視覺。

## Decisions (技術決策)

- **選擇純 CSS 資訊圖表而非 JS 套件**：為了避免載入龐大的圖表套件，我們將運用 HTML 與 Tailwind CSS 來建構資訊圖表。例如使用不同顏色與長度的進度條（利用百分比寬度）、鮮豔的背景，以及放大的字體。
- **色彩計畫**：我們將為不同的分類引入一組豐富且和諧的色彩，在視覺上區分它們，藉此取代原本單調統一的綠色資料夾圖示。
- **排版結構**：我們將使用 CSS Grid (網格) 排版，讓畫面能自動適應螢幕大小，確保在手機上不會佔用過多垂直空間，同時在電腦上看起來也很平衡。

## Risks / Trade-offs (風險與權衡)

- **風險: 進度條的百分比計算**：如果我們使用長條圖/進度條，就需要根據總文章數來計算出百分比。
  *緩解措施*: 我們可以在 PHP 中計算總數，然後利用行內樣式 (inline styles) 輸出寬度百分比。或者，我們也可以單純設計一個好看的數字視覺，不一定要強求使用真實比例的長條圖。
- **風險: 手機版的閱讀體驗**：複雜的資訊圖表在小螢幕上可能很難閱讀。
  *緩解措施*: 這個設計在窄螢幕時，會自動退化成簡單的上下堆疊排版，將閱讀體驗擺在複雜的圖形呈現之前。
